# アセット生成パイプライン（試行錯誤の記録）

ドパミン・モールのアセット（キャラクター・マップチップ・アイテム・小物）を、
画像生成モデルで作ってゲームに組み込むまでの手順書。
**まだ試行錯誤の途中。** うまくいったこと・いかなかったことをそのまま残し、
手順が安定したらこのドキュメントを更新する。

最終更新：2026-11-26（シレン風見下ろしへ移行済み）

## 全体像

1. 仕様を決める（アセット一覧、向き、フレーム数）
2. 画像生成モデルでスプライトシートを生成する
3. シートを切り出して透過 PNG にする
4. ゲームに組み込む（向き・アニメーション）
5. プレビュー画像と実機で確認する
6. コミットして Release に載せる

## 1. 仕様を決める

- 追加するアセットを一覧にする（キャラクター名・種類・マップチップの用途）。
- キャラクターは **8方向**（南・南西・西・北西・北・北東・東・南東）で描く。
  南＝正面（手前向き）、北＝背面（奥向き）。
- 歩行フレームは **2コマ**（左足前・右足前）。足の振りを大きく、交互に踏みしめるのが
  はっきりわかる絵にする（中間フレームは使わない）。
- 攻撃は専用フレームを作らず、**突進＋斬撃エフェクト**で表現する。
- マップチップの原則：**1マス＝1つのチップ**。壁は上面と前面を1つのチップに含める。
  面（上面・前面・角）を別々のスプライトに分けると、壁の位置計算が複雑になって
  描画がガチャガチャする（2026-11-26 の反省）。

## 2. シートを生成する（画像生成モデル）

### プロンプトの型

- 画風：`Retro pixel-art game sprite sheet` に見下ろし方式を付ける。
  現在はシレン風の縦方向が真っすぐな見下ろし（`top-down view, vertical direction
  straight up and down, not isometric`）。以前は2.5Dアイソメトリックだったが、
  視認性・操作性の理由で見下ろしに変更した（2026-11-26）。
- 配置：行と列をはっきり指定する（例：`3 rows x 8 columns`、行＝キャラクター、
  列＝向き）。向きの順番は必ず列挙する（南、南西、西、北西、北、北東、東、南東）。
- 背景：`solid bright magenta #FF00FF background`。切り出し時の透過キーにする。
- 区切り：`with wide gaps between cells`（スプライト同士を離す。くっつくと切り出せない）。
- 禁止事項：`no text, no shadows on the background`（影があると透過処理で残る）。

### うまくいかなかったこと

- **プログラム生成の限界**：最初は Pillow で計算生成していた（`tools/generate_tiles.py`）が、
  どうしても Y2K な雰囲気になってしまった。画像生成モデルへの切り替えが正解だった。
- **向きの取り違えの危険**：シートの列の順番をプロンプトで明示しないと、向きがずれる。
  切り出し後に必ずコンタクトシートで目視確認する（客と店員の取り違えなど）。
- **マゼンタのフリンジ**：霧やランプなど半透明に近い絵は、マゼンタ背景と混色して
  ピンクがかった縁が残る。低 alpha で描けばほぼ目立たないが、完全な解決ではない。

## 3. 切り出して透過 PNG にする

- スクリプト：`tools/slice_sheets.py`（Pillow＋scipy連結成分法）。
  マゼンタ背景を透過にし、グリッド位置で成分を割り当て、最大辺 160px に縮小する。
- 入力は WebP でも Pillow で読める。
- 出力先：`android/assets/sprites2d/`。対応表は `manifest.json` に残す。
- **切り出し後はコンタクトシートを作って目視確認する。** 向きの取り違え・欠け・
  フリンジがないかを見る。ここを省くとゲーム内で気づきにくい。
- 旧スプライトは置き換わったら削除して APK を軽くする
  （プログラム生成の `android/assets/sprites/` 34枚は 2026-11-26 に削除済み）。

## 4. ゲームに組み込む

- 読み込み：`Sprites.java`（`sprites2d/` から読込、Linearフィルタ）。
- 向き：プレイヤーと敵に「向き」（0〜7、南から時計回り）を持たせ、移動・攻撃した
  方向を向く。向きに合ったスプライトを描く。
- 歩行：移動の補間（約0.12秒）に合わせて主人公は2フレームを交互に切り替える
  （前半フレームA、後半フレームB）。足の振りを大きくした新しいシートを使い、
  プレビュー画像で2フレームの違いが目に見えることを確認する。敵は上下の跳ね＋
  向きの切り替えでよい。
- 攻撃：攻撃方向へ素早く突進して戻る（0.18秒、0.35マス）＋斬撃エフェクト（白い弧）
  ＋対象のフラッシュ（黄色い星）。
- 8方向シートがない種類（ウサギの着ぐるみ・サル・ツチノコ・雪男・獅子の神・
  3種のボス）は従来の1枚絵をフォールバックとして使う。
- 移動とキー：矢印キー／WASD は画面の方向（上＝画面の上、下＝画面の下、左＝画面の左、
  右＝画面の右）。残りの4方向は Q／E／Z／C。ゲームパッド・Fire TV リモコンの
  十字キーは画面の4方向。斜め移動も1ターンで移動できる。敵AI・視界のBFSも8方向。
- **注意：Q/E/Z/C の対応は一度間違えた。** 座標変換の数式で検証すること。
  見下ろしでは画面の上＝北（y が減る方向）、下＝南（y が増える方向）。
  正しい対応：Q＝北西(-1,-1)、E＝北東(1,-1)、Z＝南西(-1,1)、C＝南東(1,1)。
  指示の値を鵜呑みにせず、数式で確かめること。
  （旧アイソメ時代の対応：Q＝北西(-1,0)、E＝北東(0,-1)、Z＝南西(0,+1)、
  C＝南東(+1,0)。座標系が変わったら対応表も作り直すこと。）
- 向きの対応表（見下ろし）：0=南(0,1)、1=南西(-1,1)、2=西(-1,0)、3=北西(-1,-1)、
  4=北(0,-1)、5=北東(1,-1)、6=東(1,0)、7=南東(1,1)。向きとスプライトの列の
  順番（南、南西、西、北西、北、北東、東、南東）は同じ。
- 描画：タイルは `tileX(x)=x*64`、`tileY(y)=-y*64` で並べる（libGDX のワールド
  座標は Y が上向き）。描画順はペインター法で行ごとに上から下へ。
  壁チップはタイルに64x64でそのまま1枚描く（面分割の描画コードは削除済み）。
  未使用になった壁面スプライト（wall_top／wall_band／wall_corner／door）は
  `sprites2d/` から削除した。

## 5. プレビューと確認

- プレビュー生成：`tools/preview_iso.py`（ゲーム本体と同じ座標計算で 1280x720 を描く）。
  下層（明るいモール）と上層（霧とランタンの神秘）の2枚を作る。
  プレビュー画像は `samples/preview25d/`（ローカルのみ、コミットしない）。
- **実際の起動・プレイ確認は VM ではできない**（ディスプレイなし、Gradle もローカルでは
  動かない）。CI ビルド成功までが VM での確認範囲。実機（Fire TV／PC）での確認が必須。
  実機確認項目：視認性、斜め移動の操作感、ゲームパッドのボタン挙動、攻撃アニメの見た目、
  霧・オーバーレイの暗さ、壁の見え方。
- 足の踏みしめ問題（2026-11-26）：遊んだビルドは上下の跳ねだけで、足が交互に出て
  いなかった。歩行フレームは足の振りを大きくし、切り替えが実際に目に見えるか
  プレビューと実機の両方で確認する。

## 6. コミットとリリース

- `git add -A` は使わない。必要なファイルだけ個別に add する。
  （一度 `samples/` を誤ってコミットしたことがある。`samples/` は `.gitignore` 済み）
- コミットして main へ push すると GitHub Actions が自動でビルドする。
  別途 `gh workflow run` は不要（重複実行を避ける）。
- 手元の VM では Gradle が動かない（サンドボックスが TCP をブロックするため）。
  検証は CI の実行でのみ行う。失敗したらログを読んで修正し、最大3回まで再実行する。
- 成功したら `gh release view nightly` で APK と `dopamine-mall-desktop.jar` の
  両方が更新されたことを確認する。
- 日次ビルド：毎日 09:00 JST に GitHub Actions が走り、nightly Release を更新する。
  Release ページ：https://github.com/nutomu/dopamine-mall/releases/tag/nightly

## 音楽（アセット生成の補足）

- **音楽生成モデルは手元にない。** 使えるのは Spotify 再生・ナレーション生成・TTS のみ。
  BGM はシンセサイズのチップチューンで作る（`tools/generate_music.py`、Python 標準ライブラリ
  の `wave`＋`math` で方形波・三角波・正弦波を合成）。
- 作曲の充実ポイント：メロディにハーモニー（3度下）、ウォーキングベース、
  カウンターメロディ、進行の変化（ダンジョン後半 Am–F–Dm–E、ボス後半 Fマイナー寄り）、
  低いドン（サイン波）。
- OGG 変換：ffmpeg で WAV→OGG（libvorbis q4）。音楽データ 2.35MB→約310KB。
  WAV はリポジトリから削除する。
